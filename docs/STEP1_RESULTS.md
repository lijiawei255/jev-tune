# Step 1 + 2 results — numeric decision head

> [English](#step-1--2-results--numeric-decision-head) · [简体中文](#step-1--2-结果中文)


> Generated by `scripts/01_make_dataset.py` → `02_train.py` → `03_evaluate.py`.
> Everything below ran on the Windows CPU of this machine; no GPU was used.

## What was built

| Component | What it is |
| :--- | :--- |
| Plant zoo | 6 training families (FOPDT, SOPDT, 3rd-order + RHP zero, integrating, PMSM speed loop, type-1 position loop) with **per-plant actuator headroom** (1.0 / 1.6 / 2.5 × unit command) + 1 **held-out** family (two-mass resonance) |
| Expert | coordinate line search over the same 3×7 action vocabulary the decoder emits (22 sims/step) |
| Dataset | 2 000 plants × 20 steps = 40 000 states, 630 000 one-step lookahead rows |
| Head | 1D-CNN over the traces + MLP over 20 features → 3×`choice(7)` + `score(5)` + `noul`, 168 KB as ONNX |
| Value net | (state, action) → predicted cost, 26 KB, used as a one-step lookahead filter |
| Baselines | Z-N, relay autotune, simplex, CMA-ES, Bayesian optimisation, MATLAB `pidtune`, identify→`pidtune` |

## KPI 1 — decision latency (the "system-1" claim)

ONNX Runtime, 1 thread, batch 1, 2 000 repetitions:

| backend | p50 | p95 | p99 | size |
| :--- | ---: | ---: | ---: | ---: |
| ONNX Runtime (CPU) | **0.188 ms** | 0.233 ms | 0.503 ms | 168 KB |
| PyTorch eager (CPU) | 1.668 ms | — | — | 206 KB |

Parity between the ONNX graph and PyTorch: max abs difference **7.6e-06**.
Target was "decision < 1 ms"; measured **0.19 ms**, ~5× inside budget.

Full iteration on the lab model: decision 0.19 ms + Simulink Fast Restart run
**111 ms** (StopTime = 10 s, measured in `research/bench/`) ≈ 0.11 s.
Without Fast Restart the same model costs 869 ms per run, so the bridge — not
the model — would dominate.

## KPI 2 — calibration

Temperature fitted on a 10 % held-out split of the rollouts:

| axis | val accuracy (7-way) | ECE before | ECE after | fitted T |
| :--- | ---: | ---: | ---: | ---: |
| Kp step | 0.666 | 0.033 | **0.031** | 1.00 |
| Ki step | 0.690 | 0.030 | **0.011** | 0.92 |
| Kd step | 0.678 | 0.021 | **0.020** | 0.96 |
| `score` | 0.994 | — | — | — |
| `noul` | 0.969 | — | — | — |

ECE ≈ 0.02 is what makes `score`-based early stopping and `noul`-based gating
meaningful. Laya ships at ECE 0.466 for comparison.

## KPI 3 — held-out benchmark (120 plants, unseen family)

Target = 1.05 × a strong CMA-ES reference (240 simulations/plant, median J =
0.365). All methods see the same cost function, the same Z-N starting point and
the same simulation accounting.

| method | final J (median) | final J (p90) | × reference | success | sims/plant |
| :--- | ---: | ---: | ---: | ---: | ---: |
| **Jev head** | **0.468** | 1.037 | **1.29** | **45 %** | **20** |
| Bayesian opt. | 0.567 | 1.510 | 1.56 | 35 % | 20 |
| identify → `pidtune` | 0.742 | 1.705 | 1.91 | 29 % | 2 |
| relay autotune | 0.906 | **0.935** | 2.36 | 37 % | 2 |
| CMA-ES | 1.813 | 2.618 | 3.75 | 10 % | 18 |
| simplex | 2.037 | 2.879 | 4.43 | 7 % | 20 |
| Z-N | 2.322 | 3.082 | 5.74 | 6 % | 1 |

**Reading**

* The head has the lowest median cost of every method that does not know the
  model — 3.9× better than CMA-ES at the same simulation budget, 5.0× better
  than Z-N, and it reaches 1.05× of the 240-simulation reference after a
  **median of 5 experiments**.
* It no longer has a heavy tail either: p90 1.04 against BO's 1.51 and relay's
  0.94. The one baseline that still beats it in the tail is relay autotuning,
  which costs two experiments but cannot improve on them.
* `identify → pidtune` reaches 0.747 in **two** simulations. Any claim about
  learned tuning has to survive that comparison, which is why it is in the table.

## The vocabulary + zoo changes (what the two levers actually did)

| iteration | vocabulary | zoo | head median | head p90 | sims to target |
| :--- | :--- | :--- | ---: | ---: | ---: |
| v1 | 5 uniform (×0.8…×1.25) | 5 families, fixed actuator | 0.333 | 1.438 | 20 |
| v2 | **7 log-spaced (×0.5…×2.0)** | 5 families + position loop | **0.316** | **0.606** | **5** |
| v3 (shipped) | 7 log-spaced | 6 families + **variable actuator headroom** | 0.569 | 2.911 | 6 |

> All three rows were measured with the lookahead value net enabled. That net
> was later found to hurt and is now off by default, which lifts v3 to
> **0.468 / p90 1.037** — the numbers in the benchmark table above.

v2 is the strongest on this benchmark. v3 is shipped anyway because it is the
one that transfers to the real Simulink motor (see `docs/STEP4_RESULTS.md`):
tight actuators are what the lab plant actually has, and training only on
generous ones produced a policy that could not tune it. The benchmark numbers
across rows are **not** directly comparable — v3's zoo is harder for every
method (Z-N 1.95 → 2.50, BO 0.39 → 0.58).


## The agent row is now measured, not assumed

The README compares against "an LLM agent in the loop". That row used to be an
assumption (3 s per turn). It is now a measurement: `scripts/14_agent_baseline.py`
asks a hosted model (Together AI, `zai-org/GLM-5.3-Flash`, temperature 0) for the
next gain step once per experiment. Two held-out plants, 20 experiments each,
same cost function.

| | agent in the loop | Jev head |
| :--- | ---: | ---: |
| median latency per decision | **5.34 s** (p90 8.98 s) | **0.19 ms** |
| wall clock, 20 experiments | ~107 s | ~8 s |
| answers unusable (format) | **13 / 40** | 0 |
| median cost reached | 1.606 | **0.577** |

The agent is not handicapped by the prompt: it receives the same metrics the head
sees, rendered as JSON, and may answer with three integers chosen from
`[-20, -10, 0, +10, +20]`. The 13 unusable answers are truncations — a reasoning
model spends its token budget thinking and never emits the final line.

Two honest caveats: this is one model at one moment, and the number measures
*this* prompt. A better prompt or a non-reasoning model would be faster and more
parseable; the 0.19 ms figure does not depend on either.

Raw log: `research/results/agent_baseline_900.json` (every request and response).

## Objectives other than a step response

`metrics.cost_from_metrics(..., objective="step" | "tracking" | "disturbance")`
and `simulate(..., profile="step" | "ramp", disturb_amp=..., disturb_time=...)`
are implemented, and the evaluator/expert thread both through.

Measured on the disturbance-rejection task (0.4 step disturbance at t = 5 s),
zero-shot head on 20 unseen plants: **1.428 → 0.960, improving 18/20 plants**.
A specialist fine-tuned on that objective made it *worse* both times it was
tried (500 states: 0.905 → 1.072; 1 680 states: 0.905 → 1.005), so it is not
shipped. The machinery works; the transfer does not yet pay for itself at this
data budget, and that is reported rather than hidden.

## Honest caveats

1. **`pidtune` with the true model is the strongest design** (0.81 median on
   training families, zero simulations). A learned tuner earns its place only
   when the model is unavailable or wrong — the scenario this benchmark uses.
2. **The tail is the weak spot.** v2 fixed it on its zoo; v3 (shipped) traded it
   for transfer. A mixture-of-experts or a two-stage vocabulary with an explicit
   saturation-aware feature is the next lever.
3. In-distribution the head is only *competitive* with CMA-ES at equal budget;
   the measurable advantage is generalisation to unseen dynamics.
4. The expert is a greedy coordinate search, so it caps the imitation target.

## Step 1 + 2 结果（中文）

> 由 `scripts/01_make_dataset.py` → `02_train.py` → `03_evaluate.py` 生成。
> 全部在 Windows CPU 上运行，未使用 GPU。

### 构建了什么

| 组件 | 内容 |
| :--- | :--- |
| 植物动物园 | 6 个训练族（FOPDT、二阶、带右半平面零点的三阶、积分型、PMSM 速度环、type-1 位置环），并随机执行器余量（1.0 / 1.6 / 2.5 倍）；另有 1 个**留出**族（双质量谐振） |
| 专家 | 在解码器同样的 3×7 动作词表上做坐标线搜索（22 次仿真/步） |
| 数据集 | 2 000 株 × 20 步 = 40 000 状态，630 000 条一步前瞻样本 |
| 决策头 | 曲线 1D-CNN + 20 维特征 MLP → 3×`choice(7)` + `score(5)` + `noul`，ONNX 168 KB |
| 价值网 | (状态, 动作) → 预测代价，26 KB，用作一步前瞻过滤 |
| 基线 | Z-N、继电自整定、单纯形、CMA-ES、贝叶斯优化、MATLAB `pidtune`、辨识→`pidtune` |

### KPI 1：决策延迟（"system-1" 的核心主张）

ONNX Runtime，单线程，batch=1，2 000 次重复：

| 后端 | p50 | p95 | p99 | 体积 |
| :--- | ---: | ---: | ---: | ---: |
| ONNX Runtime（CPU） | **0.188 ms** | 0.233 ms | 0.503 ms | 168 KB |
| PyTorch eager（CPU） | 1.668 ms | — | — | 206 KB |

ONNX 图与 PyTorch 的最大绝对偏差 **7.6e-06**。目标是"决策 < 1 ms"，实测 **0.19 ms**。

那台实验课电机的完整一次迭代：决策 0.19 ms + Fast Restart 仿真 **111 ms**（StopTime=10 s，
见 `research/bench/`）≈ 0.11 s。不开 Fast Restart 同样模型每次 869 ms——瓶颈会是桥接
而不是模型。

### KPI 2：概率校准

在 10% 留出切分上拟合温度：

| 轴 | 验证准确率（7 选一） | 校准前 ECE | 校准后 ECE | 拟合温度 |
| :--- | ---: | ---: | ---: | ---: |
| Kp 步长 | 0.666 | 0.033 | **0.031** | 1.00 |
| Ki 步长 | 0.690 | 0.030 | **0.011** | 0.92 |
| Kd 步长 | 0.678 | 0.021 | **0.020** | 0.96 |
| `score` | 0.994 | — | — | — |
| `noul` | 0.969 | — | — | — |

ECE ≈ 0.02 是让"按 `score` 早停、按 `noul` 熔断"真正可行的前提。作为对比，
Laya 出厂 ECE 是 0.466。

### KPI 3：留出基准（120 株，未见族）

目标 = 1.05 × 强 CMA-ES 参考（240 次仿真/株，中位 J = 0.365）。所有方法同一代价
函数、同一 Z-N 起点、同一仿真记账。

| 方法 | 最终 J（中位） | J（p90） | × 参考 | 成功率 | 仿真次数/株 |
| :--- | ---: | ---: | ---: | ---: | ---: |
| **Jev 决策头** | **0.468** | 1.037 | **1.29** | **45%** | **20** |
| 贝叶斯优化 | 0.567 | 1.510 | 1.56 | 35% | 20 |
| 辨识 → `pidtune` | 0.742 | 1.705 | 1.91 | 29% | 2 |
| 继电自整定 | 0.906 | **0.935** | 2.36 | 37% | 2 |
| CMA-ES | 1.813 | 2.618 | 3.75 | 10% | 18 |
| 单纯形 | 2.037 | 2.879 | 4.43 | 7% | 20 |
| Z-N | 2.322 | 3.082 | 5.74 | 6% | 1 |

**怎么读**

* 在不掌握模型的那些方法里，决策头中位代价最优——同预算下比 CMA-ES 好 3.9 倍、
  比 Z-N 好 5.0 倍；达到 240 次参考的 1.05 倍只需**中位 5 次实验**。
* 尾部也不再重：p90 1.04，对比 BO 的 1.51、继电的 0.94。唯一在尾部仍胜出的基线是
  继电自整定——它只花两次实验，但也就止步于那两次。
* `辨识 → pidtune` 只用 **2 次**仿真就到 0.747。任何"学习型调参"的主张都必须
  过这一关，所以它在表里。

### 词表 + 动物园的两次改动（两条杠杆到底做了什么）

| 迭代 | 词表 | 动物园 | 中位 | p90 | 达目标仿真数 |
| :--- | :--- | :--- | ---: | ---: | ---: |
| v1 | 5 档均匀（×0.8…×1.25） | 5 族，固定执行器 | 0.333 | 1.438 | 20 |
| v2 | **7 档对数（×0.5…×2.0）** | 5 族 + 位置环 | **0.316** | **0.606** | **5** |
| v3（发布版） | 7 档对数 | 6 族 + **变执行器余量** | 0.569 | 2.911 | 6 |

> 上面三行都是在启用了前瞻价值网时测的。该网络后来被发现有害，现已默认关闭，
> 关闭后 v3 提升到 **0.468 / p90 1.037**——即上面基准表里的数字。

v2 在该基准上最强。之所以发布 v3，是因为**只有它能迁移到真实 Simulink 电机**
（见 `docs/STEP4_RESULTS.md`）：紧执行器才是实验台的真实情况，只训练宽松执行器
会让策略无法调它。三行之间的绝对值**不可直接比**——v3 的动物园对所有方法都更难
（Z-N 1.95 → 2.50，BO 0.39 → 0.58）。

## 智能体那行：从"假设"变成了"实测"

README 里对比的"把大模型接进环路"原本是个假设（每次 3 秒）。现在是实测：
`scripts/14_agent_baseline.py` 在 2 个留出对象、每个 20 次实验、同一代价函数下，每次实验向托管
模型（Together AI，`zai-org/GLM-5.3-Flash`，temperature 0）要一次增益调整。

| | Agent 在环 | Jev 决策头 |
| :--- | ---: | ---: |
| 单次决策延迟（中位） | **5.34 秒**（p90 8.98 秒） | **0.19 毫秒** |
| 20 次实验的总耗时 | 约 107 秒 | 约 8 秒 |
| 输出无法解析 | **13 / 40** | 0 |
| 达到的中位代价 | 1.606 | **0.577** |

提示词没有为难它：它收到与决策头同样的指标（JSON 形式），可以从
`[-20, -10, 0, +10, +20]` 里选三个整数。13 次失败是**截断**——推理模型把 token
预算花在思考上，最后那行答案没吐出来。

两个诚实的限定：这只是一个模型、一个时刻的结果，而且测的是*这个*提示词；更好的
提示词或非推理模型会更快、更可解析。但 0.19 毫秒那一侧不受提示词影响。

原始日志：`research/results/agent_baseline_900.json`（每一次请求和响应都在里面）。

## 阶跃之外的目标函数

`metrics.cost_from_metrics(..., objective="step" | "tracking" | "disturbance")`
和 `simulate(..., profile="step" | "ramp", disturb_amp=..., disturb_time=...)` 已实现，
评测器和专家生成都支持透传。

在扰动抑制任务上（t = 5 秒施加 0.4 的输入扰动）实测：零样本决策头在 20 个未见对象
上 **1.428 → 0.960，20 个里 18 个变好**。而一个在该目标上微调的专家**反而更差**
（500 状态：0.905 → 1.072；1 680 状态：0.905 → 1.005），因此不发布。机制是通的，
但以这个数据量，迁移还不划算——这条如实写出来，而不是藏起来。

## 诚实的 caveat

1. **模型已知时 `pidtune` 最强**（训练族上中位 0.81，0 次仿真）。学习型调参只有在
   模型不可得或不可信时才有正当性——这正是本基准设定的场景。
2. **尾部是弱点。** v2 在它的动物园上修好了，v3（发布版）用尾部换迁移。
3. 同分布下决策头只是**与** CMA-ES 同预算持平；可测量的优势来自对未见动力学的泛化。
4. 专家是贪心坐标搜索，因此它封顶了模仿目标。
