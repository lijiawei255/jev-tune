# 规模效应、并发与版本兼容

这份文档回答三个在"真拿去用"时才会冒出来的问题：

1. 为什么这个项目对**大批量**调参特别划算（而单台设备提升有限）；
2. MCP 服务器是阻塞的，会不会把规模效应吃掉；
3. 别人的 MATLAB 不是 R2024b，还能不能跑。

---

## 1. 规模效应：钱和时间到底省在哪

把一次调参拆成三块成本：

| 符号 | 含义 | 实测/假设 |
| :--- | :--- | :--- |
| `S` | 一次仿真（Fast Restart） | **0.111 s**（motor-valve benchmark，10 s 时长，实测） |
| `D` | 一次决策 | **0.002 s**（MATLAB 内手写前向）/ 0.00019 s（ONNX） |
| `L` | 一次 LLM 往返 | 1–10 s（**假设**，随模型而变） |
| `C` | Agent 一次工具调用的固定开销 | ≈ 1 次 LLM 往返 + 少量 token |

对 `N` 个对象、每个跑 `M` 次实验：

```
Agent 在环：   T_agent = N × M × (L + S)          + token 成本 N×M 次上下文
本项目：       T_head  = N × M × (S + D) + N × C
```

加速比 ≈ `(L + S) / (S + D)`，**当 M 越大越接近常数**，而**当 N 越大，省下的绝对时间线性增长**。

取 `L = 3 s, S = 0.111 s, D = 0.002 s, M = 20`：

| 对象数 N | Agent 在环 | 本项目 | 加速 | Agent 的 LLM 调用次数 |
| ---: | ---: | ---: | ---: | ---: |
| 1 | 62 s | ≈ 2.3 s + 启动 | ~10× | 20 |
| 10 | 10.4 min | ≈ 23 s | ~27× | 200 |
| 100 | 1.7 h | ≈ 3.9 min | ~27× | 2 000 |
| 1 000 | **17.2 h** | **≈ 39 min**（单线程） | **~27×** | **20 000** |

两个容易被忽略的收益：

* **token 成本**：Agent 在环时每一步都要把模型摘要、历史、曲线描述塞回上下文，20 000 次调用 ≈ 上亿 token；本项目是 1 000 次调用、每次一个紧凑 JSON。
* **可复现性**：LLM 决策有采样随机性和版本漂移；决策头是固定权重 + 固定种子，同一模型跑两次结果逐位相同。

> 结论：**单台设备上它只是"省事"；到 100 台以上，它才开始"省一个数量级"。**
> 这正是大型科研项目（几百个工况）和工业部署（几百台设备）值得参考的地方。

## 2. 阻塞的 MCP 服务器，会不会吃掉规模效应？

**不会吃掉，但会把它从"27×"压到"约 17×"——因为阻塞是常数因子，不是渐近项。**

原因：一次调参本身只有 2–4 秒（20 次 × 0.111 s + MATLAB 启动）。串行排队 1 000 台 = 约 1 小时；而 Agent 在环需要 17 小时。**数量级的优势仍然在。**

真正需要并发时，有三种做法（按代价排序）：

| 方案 | 做法 | 收益 | 代价 |
| :--- | :--- | :--- | :--- |
| **A. 进程池**（推荐） | MCP 服务器内部维护 N 个常驻 MATLAB 进程，各自独立 scratch 目录 | 线性加速，且省掉每次 10 s 的 MATLAB 启动 | 受 MATLAB 许可证并发数限制；内存 ×N |
| **B. `parsim` 批处理** | 在单个 MATLAB 里并行跑多组增益 | 无许可证问题 | 只适合"批量评估"，不适合"看一步走一步"的闭环 |
| **C. 多 MCP 实例** | 用户自己起多个 server，各绑一个端口/进程 | 零改动 | 需要客户端支持并发调用 |

现在的实现是"同步 + 串行"，这是**有意的默认值**：对单用户、单模型、交互式使用最稳。批量场景应该用 A，我可以按需加一个 `--workers N` 参数（一个 MCP 工具就能触发 1 000 台的任务，内部并行）。

另外，MCP 协议本身支持"工具调用返回 job id、再轮询状态"的模式。当前是同步返回，因为单次任务只有几秒；如果将来单次任务变成分钟级，就应该改成异步句柄。

## 3. 版本兼容：别人不是 R2024b 怎么办

原来的代码里有两处硬假设：MATLAB 装在 `C:\Program Files\MATLAB\R2024b`，以及 `matlab -batch` 一定可用。两处都已修掉。

**现在的发现顺序**：`MATLAB_EXE` 环境变量 → `PATH` → Windows 注册表（`HKCU\Software\MathWorks\MATLAB`）→ 常见安装目录扫描 → POSIX 路径（`/usr/local/MATLAB/*`、`/Applications/MATLAB_R*.app`）。

**启动器**：探测 `matlab -help` 是否含 `-batch`，没有就退回 `-nodisplay -nosplash -r "…; exit"`。

**能力探测**（`jev-tune matlab --probe` / MCP `tune_probe_matlab`）：

```json
{"release": "2024b", "has_fast_restart": true, "has_scope_logging": true,
 "has_pid_tune": true, "supports_batch": true}
```

**版本下限**（按用到的 API 推算）：

| 功能 | 最低版本 | 说明 |
| :--- | :--- | :--- |
| Fast Restart | R2013b | 没有它也能跑，只是每次重编译，慢 8–19× |
| Scope 数据记录 | R2014a | 否则需要改成 To Workspace + 自建 logging |
| `jsonencode/jsondecode` | R2016b | 桥接层用，低于此版本需换 XML/CSV |
| `-batch` | R2019a | 低于此版本自动退回 `-r` |
| 决策头前向 | 任意 | 纯矩阵运算，无工具箱依赖 |

**实测范围**：只有 R2024b 是真正跑通的。其他版本靠探测 + 降级逻辑，未逐一验证——这一点必须如实说，不要让用户以为"全版本支持"。

## 4. 产品逻辑不一致清单（自查）

写完上面三条后，我把"代码里隐含的假设"和"产品想给人的承诺"对了一遍：

| # | 问题 | 影响 | 状态 |
| :--- | :--- | :--- | :--- |
| 1 | MATLAB 路径写死 R2024b | 换版本直接失败 | ✅ 已修（自动发现） |
| 2 | 增益块/示波器名写死 `Gain_Kp`、`Scope_Position` | 别人的模型跑不了 | ✅ 已修（`cfg.kp_block` 等） |
| 3 | `matlab -batch` 假设 R2019a+ | 老版本失败 | ✅ 已修（回退 `-r`） |
| 4 | 只支持"三个独立增益块"的并联 PID | 用 Simulink `PID Controller` 块的模型无法直接调 | ⚠️ 未修（需要 block adapter） |
| 5 | 参考值来自 `Step × Deg2Rad` | 非阶跃输入会算错 | ✅ 已支持 `cfg.ref_source` 手动指定 |
| 6 | 代价函数固定为阶跃指标 | 跟踪/扰动抑制项目不适用 | ⚠️ 未修（需新增 metric） |
| 7 | 训练分布是 10 s / 5 ms 的阶跃响应 | `StopTime` 差太远时特征会失真 | ⚠️ 未加警告（建议 probe 时比对） |
| 8 | MCP 同步阻塞 | 批量场景吞吐受限于单进程 | ⚠️ 未修（见 §2 方案 A） |
| 9 | 训练权重在 Windows 生成 | 推理纯数值，跨平台无影响 | ✅ 无问题 |
| 10 | 名字叫 `jev-tune` | 容易被误解为"用了 Jev 模型" | ✅ README 已显式澄清 |

第 4、6、7、8 条是真正会影响"别人拿去做自己的项目"的，优先级：

1. **#6 代价函数可配置** —— 这是最常见的需求（很多人调的是跟踪/扰动抑制，不是阶跃）；
2. **#4 PID Controller 块适配** —— 决定能否开箱用于别人的 Simulink 模型；
3. **#8 并发 worker** —— 决定 1 000 台级别的实际吞吐；
4. **#7 分布漂移警告** —— 便宜，能避免"默默给出错误建议"。

这四条我建议按顺序做，每一条都能单独发布。
