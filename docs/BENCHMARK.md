# BENCHMARK

[English](#english) · [简体中文](#简体中文)

## English

One experiment is one simulated plant at one gain set. Iterative methods receive
at most 20 runs including their measured start. Fixed/one-shot methods report
their actual counts; they do not repeat an identical measurement to consume 20.
Returned gains must reproduce the reported best cost. CMA-ES and BO now measure
the shared starting set first, within budget; sampled winners are returned,
never an unmeasured optimizer distribution mean.

The main benchmark starts from analytic Ku/Tu, including simplex/CMA/BO/hill:
this is oracle prior information, not a completely model-free experiment.
Offline expert generation and fitting are separate from deployment budgets.
Shrunk-ZN factors are selected on training families, not the evaluation plants.
The 7-run sweep costs seven per plant; failures use a common fixed non-oracle
prior instead of analytic Ku/Tu backfill. Results record recovered counts,
fallback policy and prior access. A failed sweep is not successful identification.

Frozen historical tables (generated by script 03, with allocated budgets and provenance):

* [two_mass validation](https://github.com/lijiawei255/jev-tune/releases/tag/v0.10.1)
* [fixed-grid thermal test](https://github.com/lijiawei255/jev-tune/releases/tag/v0.10.1)

two_mass has been used to compare vocabularies, reject lookahead and choose
policies. thermal_deadtime was defined after training and frozen at v0.4.1;
v0.5.0 reran it after repairs and v0.6.0 reruns the monitor default, without choosing a new checkpoint on it. Neither
claim implies preregistration. The thermal result in v0.4.1 put vocabulary hill
climbing ahead of the head; that historical result remains in the changelog.
Current ranking must be read from the regenerated table even if a baseline wins.

For v0.9's descriptive budget curve, use [PRACTICAL_BUDGET](https://github.com/lijiawei255/jev-tune/blob/v0.10.2-archive/docs/PRACTICAL_BUDGET.md).
It fixes a non-oracle starting set and assumed Ku/Tu, compares the unchanged head
with hill/CMA/simplex, and reports each plant's actual simulation count alongside
returned cost. Its new outputs are separate from the tables above. The historical
`budget` field is a maximum for iterative methods; it must not be relabeled as
an observed call count for a head that can stop early. Future script-03 schema 2
adds actual mean/min/max and per-plant counts. Target-hit quantiles condition on
successful plants; use the success fraction with them, not the quantile alone.

Historical `identify+pidtune` rows must be read with their original implementation:
missing MATLAB or invalid designs could silently use analytic Z-N. New runs
explicitly record `unavailable`/`failed_design` and omit the failed arm from the
ranking, without oracle substitution. The implemented linear step probe also
rejects unsupported saturation, dead-zone and noisy-sensor cases. No earlier
number is silently repaired by this behavior change. The new practical study
does not include this baseline.

The returned-best guarantee follows from measuring the start and saving the
minimum; it holds without the rollback gate. It is not evidence of safe
exploration: trials can diverge before a best point is returned. The gate's
effect is separately measured in [robustness.json](https://github.com/lijiawei255/jev-tune/releases/tag/v0.10.1).
Per-plant gates do not suppress unrelated batch members. Trace-based risk and
coverage metrics use one record per measured transition; partial holds count.

```bash
python scripts/39_practical_budget.py --check
python scripts/39_practical_budget.py --run --output-root .local-audit/practical-replay
python scripts/39_practical_budget.py --check --output-root .local-audit/practical-replay
python scripts/03_evaluate.py --plants 120 --budget 20 --out .local-audit/benchmark-replay
python scripts/03_evaluate.py --family thermal_deadtime --plants 120 --budget 20 --out .local-audit/benchmark-replay
python scripts/16_check_claims.py
```

The replay commands use separate output directories. They run the current
implementation and therefore do not promise the frozen historical values.
For script 03, the default Markdown table now follows `--out`; `--table` can
override it explicitly. Script 39 refuses to overwrite its existing artifacts.
No new training, risk experiment or threshold selection is required.

Manifests bind source, model/data hashes, seeds and environment. Source hashes,
rather than just the parent Git SHA of a dirty worktree, identify the measured
implementation. Claims checking covers registered artifacts and marked prose;
it does not prove every historical sentence or the method's causal advantage.

## 简体中文

一次实验指一个对象在一组增益下的一次仿真。迭代方法最多20次，包含实测起点；
固定与一次性方法列实际用量，不通过重复同一测量凑满20次。返回增益必须重现所报最优代价。
CMA-ES与BO现先测共同起点并计入预算，返回实际采样赢家，不再返回未测的分布均值。

主基准的simplex/CMA/BO/hill和head均从解析Ku/Tu出发，属于oracle先验，不能称完全无模型。
离线专家数据与训练成本独立列账；缩小ZN系数在训练族选择。7次扫描逐株计费；失败后各扫描方法
采用相同固定非oracle先验，不再回填解析Ku/Tu。产物记录恢复数、回退规则和先验来源；扫描失败不算辨识成功。

以下为03脚本生成的冻结历史表，含分配预算与来源：

* [two_mass验证族](https://github.com/lijiawei255/jev-tune/releases/tag/v0.10.1)
* [固定网格热工测试族](https://github.com/lijiawei255/jev-tune/releases/tag/v0.10.1)

two_mass参与过词表、lookahead和策略选择。thermal_deadtime在训练后定义，于v0.4.1冻结；
v0.5.0修复正确性后重跑，v0.6.0再验证默认monitor，未据此选择新权重，但仍不构成预注册研究。
v0.4.1热工结果中同词表爬山优于head，该历史记录保留在CHANGELOG；当前排名以新生成表格为准，
基线胜出也照实发布。

v0.9的描述性预算曲线见[PRACTICAL_BUDGET](https://github.com/lijiawei255/jev-tune/blob/v0.10.2-archive/docs/PRACTICAL_BUDGET.md)。它固定非oracle起点与
假定Ku/Tu，将原head和hill/CMA/simplex比较，同时列逐株实际仿真次数与返回代价；新产物
独立于上面的历史表。历史`budget`对迭代方法表示上限，不能把会提前停止的head上限改称
实耗。03未来schema 2增列实际均值/最小/最大及逐株次数。达到目标的次数分位数只统计成功
对象，需与成功比例一起看，不能单独当所有对象的成本。

历史`identify+pidtune`行依其原实现解释：MATLAB不可用或设计无效时可能静默换成解析ZN。
新运行明确记录`unavailable`/`failed_design`，从排名省略失败臂，不替换成oracle；线性阶跃
探测器还会拒绝未实现的饱和、死区和噪声条件。此行为修复不暗改旧数字，新实用预算评测
也不包含该辨识基线。

最终不差于起点来自“实测起点并保存历史最小值”，关闭回滚门仍成立，不证明探索过程安全，
候选试验仍可能发散。门的实际效果单列于[robustness.json](https://github.com/lijiawei255/jev-tune/releases/tag/v0.10.1)。
门按对象执行，不影响同批其他对象。风险和覆盖率按每条真实测量转移统计，部分轴保持仍计入。

```bash
python scripts/39_practical_budget.py --check
python scripts/39_practical_budget.py --run --output-root .local-audit/practical-replay
python scripts/39_practical_budget.py --check --output-root .local-audit/practical-replay
python scripts/03_evaluate.py --plants 120 --budget 20 --out .local-audit/benchmark-replay
python scripts/03_evaluate.py --family thermal_deadtime --plants 120 --budget 20 --out .local-audit/benchmark-replay
python scripts/16_check_claims.py
```

复现命令使用独立输出目录，执行当前实现，不承诺复现冻结历史版本的数值。03默认Markdown
表现在跟随`--out`，也可显式指定`--table`；39拒绝覆盖已有产物。不需要新训练、风险实验
或阈值选择。

manifest记录源码、权重、数据hash、种子和环境；未提交工作区仅记录父SHA不足以标识被测代码，
所以还记录源码hash。claims检查已注册产物及标记正文，不证明全部历史文字或类型接口的因果优势。
